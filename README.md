2) Jiro في سطرين — وتصميم الضمان المتفق عليه
Jiro سوق لبيع وشراء المستعمل، فلوسه محجوزة في ضمان (Escrow) لحد ما المشتري يستلم السلعة ويؤكدها. الشعار:Deal with Confidence. الإطلاق الأول: موبايلات فقط في القاهرة. الهوية: كحلي غامق#16294Dوبرتقالي#FF7A1Aبنسبة تقريبية 70% كحلي و30% برتقالي، واللوجو المعتمد هو نسخة الابتسامة الهلالية (Crescent Smile) مع الشعار متمركزًا تحتها بالضبط.
قواعد الإثبات المتفق عليها لـ Jiro
•	تأكيد التوصيل من شركة الشحن (تتبّع وإثبات تسليم ظاهر للطرفين) — مش من كلام المشتري لوحده، عشان محدش يدّعي عدم الاستلام زورًا ويطلب استردادًا.
•	شركة الشحن تُثبت التوصيل فقط ، ولا تفتّش على السلعة.
•	البائع: يصرّح بكل العيوب بصدق مع صور حقيقية + فيديو تعبئة (Packing Video) + لقطة شاشة من Device Care تُظهر حالة الجهاز وإمكانياته: إيه شغال وإيه فيه غلط.
•	المشتري: فيديو فتح العلبة (Unboxing) يثبت حالة الشكل الخارجي عند الاستلام + لقطة Device Care عند الاستلام.
•	زر نزاع (Dispute) يجمّد تحرير الفلوس لحد ما الدعم يراجع الأدلة.
•	نافذة الفحص 48 ساعة من التوصيل، و تحرير تلقائي بعد 72 ساعة من التوصيل لو مفيش نزاع.

PiNet — شرط Pi Next لكل تطبيق
PiNet يخلي جزءًا من تجربة تطبيقك مفتوحًا لناس بره منظومة Pi من متصفح عادي بدون Pi Browser — مفيد للدعوات والتجربة الأولى. التصميم الصح لـ Jiro:صفحة تصفّح عامة بدون تسجيل دخول(عرض المنتجات) على PiNet، ولا تستدعيPi.authenticate()إلا لما المستخدم يقرر يسجّل أو يشتري أو يبيع — عندها ينتقل لـ Pi Browser.
5) يعني إيه SDK و API؟ — بلغة بسيطة خالص
Pi SDK — «عدّة الواجهة».مكتبة JavaScript صغيرة بتحطها في صفحة تطبيقك بسطر واحد. هي اللي بتخلي تطبيقك «يكلم» Pi Browser: يطلب تسجيل دخول المستخدم، ويفتح نافذة الدفع. بتشتغل في المتصفح (الواجهة) فقط. مفيش تثبيت npm — سطر<script>وخلاص، ولازم يكون موجودًا في كل البيئات حتى الإنتاج؛ Pi Browser مش بيحقنه لك تلقائيًا.
Pi Platform API — «عدّة السيرفر».عناوين إنترنت (Endpoints) سيرفرك بيكلمها من ورا الستار بمفتاحك السري: يتحقق من هوية المستخدم، ويوافق على دفعة، ويكمّلها. العنوان الأساسي:https://api.minepi.com/v2. دي مش للمتصفح أبدًا — مفتاحها لو ظهر في كود الواجهة فده اختراق أمني خطير بنص الوثائق.
التضمين والتهيئة — أول سطور في حياتك مع Pi
نادِPi.init()قبل أي دالة SDK تانية. تركsandbox: trueفي الإنتاج يكسّر الدخول والدفع للمستخدمين الحقيقيين — من أشهر الأخطاء. جرّب تطبيق Pi Bakery التجريبي الرسمي على Testnet من demo.pi وافتح كوده على GitHub (روابطه في صفحة Getting Started).
تسجيل الدخول: Pi.authenticate()
الصلاحية (Scope)	بتديك إيه وامتى تحتاجها
username	اسم مستخدم Pi — اطلبه دايمًا، ومعه payments من الأول عشان نفس الجلسة تقدر تدفع بعدين.

6) ربط الدفع بـ Pi: مصافحة من 3 مراحل
الدفع في Pi مش زرار وخلاص — هو مصافحة بين الواجهة وسيرفرك وشبكة Pi. لو فهمت الرسمة دي فهمت 80% من الشغل:
المبلغ 137 Pi في المثال هو نفس مبلغ تجربة الديمو التي اختبرتها بنفسك: اخترت موبايلًا وأكملت Buy with Pi ووصلت لرسالة «payment held in escrow». حقل memo يظهر للمستخدم في شاشة التأكيد، و metadata سجلّك الداخلي لربط الدفعة بطلب Jiro.
الخطوة على السيرفر	الطلب بالضبط
الموافقة (Approve)	POST https://api.minepi.com/v2/payments/{paymentId}/approve بهيدر Authorization: Key <PI_API_KEY> — وقبلها تأكد من المنتج والسعر والمشتري من قاعدة بياناتك أنت.
الإكمال (Complete)	POST .../payments/{paymentId}/complete بنفس الهيدر وجسم { "txid": "..." }
التحقق من الهوية	GET /v2/me بهيدر Bearer <accessToken>
إلغاء سجل دفعة	POST .../payments/{id}/cancel — يلغي السجل فقط، لا يعكس معاملة تمت على السلسلة.
إنشاء دفعة A2U	POST /payments بمفتاح السيرفر وجسم { "payment": { "amount", "memo", "metadata", "uid" } }
الدفعات المعلّقة (سيرفر)	GET /payments/incomplete_server_payments — دفعات A2U اتعملت ولسه بلا tx، أو اتبعتت ولسه لم تكتمل.

مفتاح APIفي ملف.envعلى السيرفر فقط (PI_API_KEY=...وتشغيلnode --env-file=.env server.js) — ولا يطلع في كود الواجهة ولا يترفع على Git أبدًا. الوثائق تصف تسريب مفتاح السيرفر للمستخدمين بأنه اختراق أمني خطير.
خلي مسارات approve/complete «Idempotent»:الـ callbacks بتعيد المحاولة كل ~10 ثواني لحد ما المؤقّت يخلص، فمسارك هيتنده أكثر من مرة لنفس الدفعة — صمّمه بحيث التكرار ميعملش تسليمًا أو خصمًا مزدوجًا، واحكم كل شيء بحالة الدفعة في قاعدة بياناتك.
Sandbox = Testnet Pi(فلوس تجريبية بلا قيمة) بنفس سلوك الحقيقي. الإنتاج = Mainnet + محفظة مهاجرة، والمستخدم نفسه لازم تكون محفظته مهاجرة عشان يدفع.
حالة الدفعة (PaymentDTO)فيها أعلام:developer_approved،transaction_verified،developer_completed،cancelled،user_cancelled— ابني منطق طلباتك عليها، ومعهاidentifierوuser_uidوamountوfrom_address / to_addressوtransaction: { txid, verified }.

العَرَض	السبب الغالب

401 من Platform API	استخدمت Bearer بدل Key، أو مفتاح Testnet ضد Mainnet (ولّد مفتاحًا جديدًا لتطبيق Mainnet)
نافذة الدفع لا تتفاعل أبدًا	موافقة السيرفر (Approve) لم تتم
الدخول/الدفع مكسور في الإنتاج	sandbox: true لسه شغالة
طلب اتعلّم «مدفوع» والفلوس ما اتحركتش	وثقت في الواجهة بدل رد /complete (هجوم الـ SDK المهكّر)
تسليم أو خصم مزدوج	مسارات approve/complete مش idempotent
كل معاملات Mainnet تفشل	محفظة التطبيق غير منشأة، أو المطوّر بلا محفظة مهاجرة

7) الضمان (Escrow) على Pi: الحقيقة وتصميم الحل
حقيقتان لازم تبني عليهما كل حاجة:(1) Pi لا يوجد فيها API ضمان جاهز في الوثائق. (2) بنص الوثائق: «بمجرد حدوث معاملة على البلوكتشين، لا يمكن عكسها» — الدفع النهائي نهائي. فالضمان عندك = حجز على مستوى التطبيق، مش خاصية شبكة.
التصميم العملي لـ Jiro
أدوات A2U على السيرفر:Pi يدعم رسميًا مكتبات خلفية لـ Node.js (pi-nodejs) و Ruby (pi-ruby)؛ Python/PHP مجتمعية حتى الآن — وده سبب تاني لاختيار Node. ترتيب A2U الآمن: أبلِغ Pi بالدفعة قبل التنفيذ على السلسلة، نفّذ، ثم أبلِغ مرة أخرى — ده بيمنع الدفع المزدوج لو السيرفر وقع في النص. المطور مسؤول وحده عن إدارة محفظة التطبيق وأصولها، والواجهات مقدمة كما هي بلا ضمانات.
الأدلة:خاصيةPi.shareFileالجديدة موصوفة رسميًا بأنها تنفع سوقًا يشارك فيه رائد إيصالًا أو صور سلعة متنازع عليها — لكنها وسيلة مشاركة فقط، والتخزين عليك (القسم 10).

8) الـ Staking: إزاي ترفع ترتيب Jiro في الدليل؟
نعم، موجود رسميًاواسمهEcosystem Directory Staking: أي رائد أو شركة يقدر يحجز (Stake) كمية Pi على Mainnet لصالح تطبيق بيختاره، والحجز ده يرفع ترتيب التطبيق مباشرة في واجهة منظومة Pi (الدليل اللي الناس بتتصفح منه التطبيقات داخل Pi Browser) — ظهور أكثر = زيارات أكثر. صفحة Pi Next نفسها تحطه تحت «التوزيع»: المطورين يقدروا يحجزوا Pi أو يحرّكوا مجتمعهم لرفع ترتيبهم.
•	مش زر في كودك: الـ Staking خاصية في Pi Browser/الدليل يستخدمها الناس — مش دالة SDK تضيفها. شغلك أنت: تطلب وتشجّع وتحفّز.
•	بدون عوائد من الشبكة: بنص Pi: لا توجد مكافآت Pi على مستوى البروتوكول — مش Staking بعائد. أي حافز (مزايا، شارات، خصومات) قرارك أنت كتطبيق.
•	الأصل بيرجع: المبلغ المحجوز يرجع لصاحبه عند انتهاء مدة الحجز، وخلال المدة يكون مقفولًا لا يُتداول ولا يُنقل.
•	الحد الأدنى والمدد المتاحة غير مذكورة في الصفحات الرسمية المقروءة — اتأكد منها من واجهة المنظومة داخل Pi Browser وقت الحجز (تبويب PiApps).
خطة Staking عملية لـ Jiro
20.	احجز مبلغًا رمزيًا بنفسك عند الإدراج كبذرة، واطلب من أوائل البائعين/المشترين الراضين الحجز لصالح Jiro.
21.	حوافز من عندك (أفكار تصميمك أنت، مش وعود Pi): شارة «بائع موثّق» أو خصم عمولة للحاجزين — وتقدر تتحقق برمجيًا لو اتفتح لك Staking Data API (بيرجع «الحجز الفعّال» = المبلغ + تعزيز حسب المدة، خاص بتطبيقك فقط) — لكن الوصول له حاليًا بقائمة بيضاء (Whitelist) فقط ولا توجد عملية تقديم عامة منشورة.
22.	لا توعد الحاجزين بأي عائد — مفيش عائد بروتوكولي، والوعد الكاذب يدمّر ثقة السوق كله.
23.	افتكر الحدود: الحجز يشتري ظهورًا مش مبيعات؛ أي منافس يقدر يحجز أكثر منك؛ والفلوس المحجوزة مقفولة طوال المدة (تكلفة فرصة).
قنوات ظهور تانية رسمية (من غير Staking)
•	أقسام جدارة في الدليل الجديد: Bookmarked • Rising Apps • Discover • "Pioneers Keep Coming Back"
•	Pi Ad Network — بتقديم في البوابة للتطبيقات المؤهلة.
•	إشعارات داخل التطبيق (حتى 20 مستخدمًا بدون موافقة إضافية مبدئيًا، وأكثر من كده بموافقة).
•	PiNet للمشاركة بره Pi Browser.
•	مبادرة نمو التطبيقات — حتى 20M Pi (التفاصيل لاحقًا).
لاحظ إن قسم"Pioneers Keep Coming Back"والاحتفاظ بالمستخدمين هو نفسه وقود جوائز تفاعل المجتمع — يعني تجربة كويسة ترجع الناس = ترتيب أعلى + فرصة جائزة أكبر.

10) عدّة الشغل: هتبني بإيه بالضبط؟
الاختيارات دي توصية لمبتدئ بيبني لوحده، ومبنية على مثال Pi الرسمي نفسه (Build an App) — Pi لا تفرض غيره.
الطبقة	الاختيار	ليه هو ده
الواجهة	HTML + JavaScript عادي في البداية (نفس شرح Pi الرسمي حرفيًا)، وبعد الراحة انتقل لـ React/Next.js لو حبيت	بيحمل SDK بسطر script وينادي Pi.init قبل أي شيء. ممنوع تعمل تسجيل دخول خاص بيك — دخول Pi فقط. الوثائق تحذر من استبدال SDK بمكتبة وسيطة.
السيرفر (إلزامي)	Node.js + Express — مسارات: /api/verify و /api/payments/approve و /api/payments/complete	ده مثال Pi الرسمي نفسه، ومكتبة A2U الرسمية ( pi-nodejs ) معمولة له. المصافحة مستحيلة من المتصفح ومفتاح API لازم يعيش هنا.
قاعدة البيانات	Postgres (مثل Supabase أو Neon — فيه طبقة مجانية)	جداول: مستخدمون (uid/username)، منتجات، طلبات (آلة الحالات)، دفعات (paymentId + txid + أعلام الحالة + حماية من التكرار)، أدلة، نزاعات.
تخزين الفيديو والصور	تخزين كائنات: Supabase Storage أو Cloudinary أو S3	فيديوهات التعبئة والفتح ولقطات Device Care — Pi لا تستضيف أدلة نزاعات، وتخزين Pi المحلي محدود وبقائمة بيضاء وغير مضمون الدوام.
الاستضافة	أي مضيف HTTPS عام: Vercel / Netlify / Render / Railway + دومين تملكه	شرط رسمي وحيد: رابط إنتاج HTTPS عام + ملف validation-key.txt في جذر الدومين على طول.
الشحن والتتبع	سيرفرك يخزن رقم التتبع وحالته؛ تأكيد التوصيل بفحصك أنت (API شركة شحن/ويب هوك أو تأكيد يدوي)	لا يوجد تكامل شحن في Pi — مشغّل تحرير الضمان مسؤوليتك أنت. اختر شركة شحن بتتبّع ظاهر للطرفين.
التجربة	Sandbox + تطبيق Testnet + حسابك الشخصي	لا توجد آلية «مستخدمي اختبار» رسمية وُجدت في الوثائق — التجربة بحسابك عبر كود تفويض Sandbox.
مساعدة ذكاء اصطناعي (اختياري)	وكلاء MCP في Developer Web Console	معلن رسميًا في القمة: يقدروا يسجّلوا ويضبطوا ويدمجوا الدخول والدفع بموافقتك — راجع كل سطر يكتبوه ضد الوثائق.

13) أسئلة لسه مفتوحة — محدش يجاوبك عليها من بره Pi
التقديم النصفي: إمتى وبأي صيغة؟
غير منشور على صفحة Pi Next — التفاصيل بالإيميل للمسجلين فقط. سجّل بدري وانتظر الإيميل.
موافقة Outgoing Wallet (دفع البائعين على Mainnet) هتاخد قد إيه؟
المعايير والمدة غير منشورة في الوثائق المقروءة. ده المسار الحرج للإطلاق الحقيقي — قدّم بدري ولا تفترض توقيتًا.
هل التطبيق المقدّم للهاكاثون لازم يكون Mainnet؟
صفحة Pi Next لا تنص صراحة — التحكيم يقيس التوافق مع إرشادات Mainnet. افترض أن الحكّام يتوقعون تطبيقًا شغالًا (عرض Testnet/Sandbox مقبول غالبًا للتحكيم) وأن الإدراج الكامل هو الهدف الأبعد، وأكّد من تعليمات الـ Console بعد التسجيل.
كام رسوم Pi على الدفعات؟ وكام حد الـ Staking الأدنى ومدده؟
الاتنين غير موجودين في المصادر الرسمية المقروءة. لا تخمّن أرقامًا — رسوم الدفع: لا تذكرها؛ الـ Staking: اتأكد من واجهة المنظومة وقت التنفيذ.
مبادرة الـ 20M Pi: مين مؤهل وبياخد كام؟
«ستُعلن لاحقًا» بنص مدونة القمة. ميزانية مشتركة بين التطبيقات المؤهلة، مش 20 مليونًا لكل تطبيق، والتقسيم الدقيق لجوائز تفاعل المجتمع (150,000 USDT لفريقين كحد أقصى) غير منشور أيضًا.
إيه اللي لسه لازم أقرأه بنفسي قبل التثبيت النهائي؟
نص إرشادات العلامة التجارية (Trademark Guideline)، شروط استخدام المطورين، وخطوات تسجيل PiNet الدقيقة — مرتبطة من صفحات Pi Next والإدراج لكن نصوصها الكاملة لم تُستخرج في هذا البحث. اقرأها قبل تثبيت الاسم واللوجو والدومين وسياسة الخصوصية.
